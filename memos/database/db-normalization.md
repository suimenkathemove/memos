# データベースの正規化

正規化とは、データの冗長性をなくしていく作業のこと。
正規化により、次のような更新時異常(anomaly)を防げる。

- 挿入異常: データを登録するのに、本来関係のない他のエンティティのデータまで必要になる
- 更新異常: 1つの事実を修正するのに、複数のレコードを更新しなければならない
- 削除異常: あるレコードを削除すると、別に残しておきたい事実まで消えてしまう

正規化を進めるほどデータの整合性は高まるが、テーブルの数が増え、結合を多用する必要があり、検索性能が劣化する。

通常の実務では、第三正規形までを考えればよい。

## 第一正規形

第一正規形は、1つのセルの中には1つの値しか含まないようにすること。

## 第二正規形

主キーの一部に対して従属する列がある場合、この関係を部分関数従属といい、すべての列に対する場合は完全関数従属という。
第二正規形は、部分関数従属を解消し、完全関数従属のみのテーブルにすること。

## 第三正規形

第三正規形は、推移的関数従属を解消すること。

## ボイス-コッド正規形

非キーからキーへの関数従属を解消すること。
第三正規形をより厳密にしたもの。

## 第四正規形

関連エンティティの関連を1つにすること。

## 第五正規形

関連がある場合は関連エンティティを作ること。
