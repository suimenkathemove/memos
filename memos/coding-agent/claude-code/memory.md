# メモリファイル

Claude Code のメモリは2系統ある。どちらも会話開始時に読み込まれる。

|            | CLAUDE.md / rules | 自動メモリ                             |
| ---------- | ----------------- | -------------------------------------- |
| 誰が書くか | 自分              | Claude                                 |
| 内容       | 指示・ルール      | 学習・パターン                         |
| 保存先     | リポジトリ内      | `~/.claude/projects/<project>/memory/` |

- `/context`
  - 現在のコンテキストの内訳をトークン数つきで表示。
- `/memory`
  - 読み込み済みメモリファイルの確認・編集ができる。
- claude --debug で起動
  - どのファイルをどの順で読んだかがログに出る。

## CLAUDE.md

毎会話の冒頭で必ず読み込まれるファイル。
コードから推測できない永続的コンテキストを与える。

~/.claude/CLAUDE.md: ユーザーレベルのもの
CLAUDE.local.md: プロジェクト単位ではあるが、ユーザーレベルのもの
サブディレクトリのCLAUDE.md

200行以下を目標にする。

### 書くべき項目

- プロジェクトの目的
- アーキテクチャ（責務・依存の方向）
- コードスタイル
- コマンド
- Git運用
- 注意事項
- やらないこと
  - 意思決定の自動化はしない
  - ファイル整理の自動化はしない
- 技術ルール
  - パッケージバージョンは固定する
- セキュリティルール
  - APIキーをハードコードしない
  - 破壊的gitコマンドは確認を取る

### 書かない項目

見れば分かる情報は書かない。
コンテキストの無駄になる上、リファクタで陳腐化して齟齬が発生する可能性がある。

- ディレクトリ構成の網羅的な列挙 → 代わりに「どこに何を置くか」の規約だけ書く
- 依存パッケージ一覧 → `package.json` を読めば分かる

### `@imports` システム

`@path/to/file` で他のファイルをインポートできる。相対パスはインポート元のファイル基準。
再帰的にインポートでき、最大4ホップ。

```md
See @README.md for project overview
See @docs/api-patterns.md for API conventions
```

**インポートされたファイルは起動時に展開されてコンテキストに入る。**
分割しても総量は減らないので、コンテキスト削減の手段にはならない。

有効な使いどころ:

- `@AGENTS.md` — 他ツール向けの指示ファイルと本文を共有する
- `@~/.claude/my-project-instructions.md` — worktree 間で個人設定を共有する

### `/doctor`

CLAUDE.md のトリム案を提示する。

定期的に実行し、古い指示や衝突する指示も併せて削除する。

## .claude/rules/

指示を複数ファイルに分割する仕組み。

`paths` frontmatter なし → `.claude/CLAUDE.md` と同じ優先度で起動時に読み込まれる。

### パススコープルール

`paths` に glob を書くと、一致するファイルを Claude が読むときにだけ読み込まれる。
CLAUDE.md が肥大化してきたらこちらに逃がすと、コンテキストを節約できる。

```markdown
---
paths:
  - "src/api/**/*.ts"
---

# API 開発ルール

- すべての API エンドポイントは入力検証を含める
```

### サブディレクトリの CLAUDE.md との違い

どちらも「特定の範囲だけに効く追加指示」だが、スコープの決まり方と置き場所が違う。

### ユーザーレベル

`~/.claude/rules/` はマシン上の全プロジェクトに適用される。
スコープは `~/.claude/CLAUDE.md` と同じで、違うのは分割できるかと条件付きで読めるか。

|                  | `~/.claude/CLAUDE.md` | `~/.claude/rules/*.md`                     |
| ---------------- | --------------------- | ------------------------------------------ |
| ファイル数       | 1つ                   | 複数                                       |
| 読み込み         | 常に全文              | `paths` あり → 一致ファイルを読むときだけ  |
| コンテキスト消費 | 常に全量              | パススコープなら必要時のみ                 |
| 共有             | コピー                | シンボリックリンクで他プロジェクトと共有可 |

`paths` を使わないなら両者は実質同じ。分ける意味があるのは次の場合。

- 言語・ファイル種別ごとの個人ルール（`paths: ["**/*.ts"]` にすれば他言語のプロジェクトではコンテキストを食わない）
- 個人ルールが増えてきたときの整理（`preferences.md` / `workflows.md` など）

全プロジェクトで常に効かせたい少数の指示なら `~/.claude/CLAUDE.md` 一枚で十分。

読み込み順は 管理ポリシー → ユーザー → プロジェクト → ローカル で、後に読まれたものが優先。
これはユーザーレベル rules 特有の性質ではなく、CLAUDE.md も同じ。

## 自動メモリ

Claude 自身が書くメモ。
デフォルトでは有効（`autoMemoryEnabled` / `/memory` で切替）。
`~/.claude/projects/<project>/memory/` に保存され、同一 git リポジトリの全 worktree で共有される。

- `MEMORY.md` — インデックス。**先頭200行 or 25KB まで**が毎セッション読み込まれる
- トピックファイル（`debugging.md` など）— 起動時には読まれず、必要時にオンデマンドで読まれる
